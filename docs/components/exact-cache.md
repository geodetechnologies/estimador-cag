# Exact estimation cache primitives

`app.cache.exact.ExactCache(backend=None, *, enabled=False, ttl_seconds=86400)` is an isolated, opt-in cache for **stateless typed estimations**. It is not wired into the application and does not cache conversational turns or session state. Construction opens no connections. When disabled, `get` and `set` never access the backend. The caller must explicitly enable it and inject an `app.cache.base.AsyncCacheBackend`; the protocol requires async `get(key)` and `setex(key, ttl_seconds, value)` methods and imports no Redis package.

`await cache.get(request, *, prompt_version, model)` returns a validated `EstimationResult` or `None`. `await cache.set(request, result, *, prompt_version, model)` returns `None`; only revalidated results are written. The default retention is 24 hours; a configured TTL must be a positive integer in seconds. Missing backends, backend errors, malformed entries, invalid results and mismatched stored identities are misses or best-effort no-op writes, without logging their contents. Cancellation is not swallowed.

`exact_cache_key(request, *, prompt_version, model)` hashes canonical JSON containing the typed request fields (description, project type, detail level, output format), prompt version and model with SHA-256, under the `estimation:exact:v1:` namespace. Boundaries are encoded as JSON fields; raw request text is not part of the key. The stored JSON envelope holds the key identity and result, both checked on retrieval. The digest and envelope do not authenticate an untrusted backend.

Cache values contain potentially private derived estimation content. Hashing keys is not encryption and does not prevent guessing low-entropy inputs. Anyone enabling a backend must independently assess access control, retention, transport security and data-handling obligations; this component does not establish tenant or session isolation. Enabling infrastructure, integrating the cache and selecting a model/prompt version are caller responsibilities.
