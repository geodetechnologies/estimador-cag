# Semantic estimation cache primitives

`SemanticCache(backend=None, embedder=None, *, enabled=False, ttl_seconds=86400, threshold=0.95)` is an isolated opt-in primitive for **stateless typed estimations**; it is not wired into the application and must not be used for conversations or session state. Construction makes no connection. When disabled, or either dependency is absent, `get` and `set` never call either dependency. The caller injects the T4 `AsyncCacheBackend` (`get` and `setex`) and an async embedder with `embed(text)` returning a numeric vector. No Redis or provider implementation is included.

`await cache.get(request, *, bucket, prompt_version, model, embedding_model)` returns a validated `EstimationResult` or `None`. `await cache.set(request, result, *, bucket, prompt_version, model, embedding_model)` returns `None`. The explicit nonempty bucket is a caller-chosen isolation boundary, not authentication; callers must scope it appropriately for tenants and other access policies. Each bucket also separates project type, detail level, output format, prompt version, estimation model and embedding model. The caller must ensure the injected embedder actually corresponds to `embedding_model`. Descriptions are embedded, not included in the hashed key. Bucket keys are SHA-256 hashes of canonical JSON under `estimation:semantic:v1:`.

Each bucket holds **one** most recently written representative, not a nearest-neighbor index. A write replaces that bucket's previous entry and resets its TTL (default 24 hours; positive integer seconds required); concurrent writes are last-writer-wins according to the backend. On lookup, a valid stored vector and the query embedding must have equal dimensions and cosine similarity at least the threshold, inclusive. Threshold must be finite and between 0 and 1. Vectors must be nonzero, finite numeric sequences of 1–4096 dimensions. Invalid entries, invalid requests/results/vectors, missing dependencies and backend or embedder failures are silent misses or no-op writes; cancellation propagates. Reads limit payload size to one million bytes/characters. The stored key and result are validated but are not authenticated against a malicious backend.

The backend stores derived embeddings and estimation results, both potentially sensitive. Hashed keys are not encryption and can be guessed; embeddings may reveal information about the description. Semantic similarity is not proof that two requests are interchangeable, and a matching result can be wrong. Anyone enabling this component must assess isolation, access controls, transport, retention, embedding-provider disclosure, similarity threshold and suitability for their application. No external traffic or cache integration is enabled by these primitives.
